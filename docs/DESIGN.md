# Устройство Skhoron-2FA

## Где живёт секрет

После добавления записи секрет TOTP существует только как HMAC-ключ в Android Keystore
(`android/.../KeystoreHmac.kt`). Приложение не хранит его ни в файле, ни в SharedPreferences
и прочитать его обратно не может: наружу выходит только результат HMAC. Метаданные записи
(издатель, аккаунт, алгоритм, цифры, период, имя ключа) лежат отдельно в `EntryStore.kt`.

Следствие, которое надо знать заранее: **из приложения нельзя повторно выгрузить секрет**.
Резервную копию нужно делать в момент добавления, пока секрет ещё известен.

## Резервная копия (вариант A)

Секрет на устройстве после добавления не хранится, поэтому приложение сразу после добавления предлагает
сохранить зашифрованный файл (`BackupController`): пароль не короче 8 символов с подтверждением,
Argon2id (64 MiB, 3 прохода, 4 потока) в фоновом потоке, запись через системный выбор места (SAF).
Можно пропустить, тогда при потере телефона этот аккаунт не восстановить. Восстановление: кнопка
«Восстановить из копии», файл и пароль. Записи, которые уже есть по метаданным, пропускаются; HOTP не
восстанавливается (его в приложении пока нет).

Ограничения:

- Один файл на одно добавление, а не общий архив.
- Пароль проходит через `String` (в памяти его не обнулить), как и ввод из `EditText`.
- Argon2id в Android нет, он написан на чистой Java (`Argon2id.java`). Сверен с OpenSSL (Python `cryptography`)
  на 12 векторах, включая вектор из RFC 9106 (`core/test-vectors/argon2id.tsv`). Защиты от всех побочных каналов
  нет, и работает он медленнее нативного. Время на телефоне не измерялось.
- Забытый пароль или потерянный файл означают, что восстановления нет.

## StrongBox и Knox Vault

По документации Android, StrongBox поддерживает из HMAC только HMAC-SHA256 с ключом от 8 до 64 байт.
Поэтому:

- SHA-256 TOTP с ключом 8–64 байта может лечь в StrongBox (на Samsung это Knox Vault, если он есть в модели);
- SHA-1 (самый частый вариант) и SHA-512 всегда попадают в TEE, а не в StrongBox.

`KeystoreHmac.importSecret` сразу выбирает путь по этому правилу, а `securityLevel()` показывает,
куда ключ реально лёг. Лицензия Samsung и Knox SDK не нужны: используется обычный Keystore API.

## Разблокировка

| Режим | Как работает | Особенности |
|---|---|---|
| `TIMED` (по умолчанию, 60 с) | Один вход (биометрия или PIN устройства) открывает ключ на 60 секунд | Удобно: все коды видны в окне. Инвалидация при добавлении отпечатка не действует (в документации она только для ключей с авторизацией на каждое использование) |
| `EVERY_USE` | Каждый код требует биометрию через `BiometricPrompt.CryptoObject(Mac)` | Строже. Ключ становится недействительным при добавлении нового отпечатка. Кнопки в интерфейсе пока нет, но `KeystoreHmac` и `UnlockGate` режим поддерживают |

Дополнительно: `setUnlockedDeviceRequired(true)`, `FLAG_SECURE` (нет скриншотов и превью в списке
приложений), `allowBackup=false`, в манифесте нет разрешения `INTERNET`.

## Согласованность записей и ключей

Запись (`EntryStore`, SharedPreferences) и ключ (Keystore) создаются двумя шагами, одной операцией их не сделать.
Порядок и последствия сбоя:

- Добавление: сначала ключ, потом запись. Если запись не сохранилась, ключ удаляется сразу. Если процесс убит
  между шагами, ключ-сирота удаляется при следующем запуске (`reconcileKeys`).
- Удаление: сначала запись, потом ключ. Сбой между шагами оставляет сироту, её тоже уберёт `reconcileKeys`.
- Список читается построчно. Если JSON битый или есть нечитаемые записи, добавление и удаление отключаются,
  а ключи **не удаляются** (иначе можно уничтожить живые). Записи сохраняются через `commit()`, результат проверяется.
- Запись без ключа показывается как «ключ отсутствует».
- Длина `otpauth://` строки ограничена 2048 символами (ядро Python и Java).

## Что защищает и что нет

- Копирование файлов приложения (в т.ч. через root или бэкап) секрета не даёт: в файлах его нет.
- Использовать ключ без устройства нельзя: он не покидает Keystore.
- Если злоумышленник держит разблокированный телефон в окне `TIMED`, он может получить коды.
  Для строгого режима нужен `EVERY_USE`.
- Скомпрометированный сервис, фишинг и подмена кода пользователем от TOTP не защищают.

## Ядро

`core/jvm` (Java, без зависимостей) считает усечение HOTP и окно TOTP; HMAC подставляется снаружи
(`Totp.HmacFunction`): в тестах это `javax.crypto.Mac` с программным ключом, в Android это `Mac`
с ключом из Keystore. `core/reference-python` повторяет те же алгоритмы независимым кодом и
добавляет импорт Google Authenticator и зашифрованный экспорт.
