# Сборка APK на GitHub Actions

Workflow: `.github/workflows/build.yml`. Он не запускался: проверен только разбор YAML и правила из
`tools/static_check_android.py`. Первый запуск может упасть на мелочи, лог покажет где.

## Как получить APK

1. Загрузите проект в репозиторий GitHub (ветка `main`).
2. Actions -> `build` -> Run workflow (или просто push). Сначала идёт `core-tests` (те же проверки, что `tools/verify.sh`),
   потом `apk`.
3. В конце задания `apk` скачайте артефакт `Skhoron-2FA-unsigned` (хранится 7 дней). Это `app-release-unsigned.apk`.
4. Подпишите у себя (один раз создайте ключ):

```
keytool -genkeypair -v -keystore skhoron2fa.jks -alias skhoron2fa -keyalg RSA -keysize 4096 -validity 10000
tools/sign-apk.sh app-release-unsigned.apk skhoron2fa.jks Skhoron-2FA.apk
```

Ключ `.jks` храните только у себя и сделайте его резервную копию: без него обновить установленное приложение нельзя.
Не коммитьте его в репозиторий.

## Что попадёт в APK

- Скомпилированный код приложения и ядра `core/jvm/src`, библиотеки androidx (appcompat, biometric и их зависимости), манифест.
- В APK нет секретов и аккаунтов: при сборке их нет нигде. Тестовые векторы и тесты в APK не входят.
- Сборка не минифицирована (имена классов читаемы). Для проекта с открытым кодом это нормально.
- Подписи в APK нет, пока вы не подпишете его сами.

## Что остаётся на GitHub

- Исходники, логи заданий и артефакт на 7 дней. Секретов в workflow нет, поэтому в логах им взяться неоткуда.
- Ключа подписи на GitHub нет и не должно быть: поэтому APK собирается неподписанным.

## Оставшиеся риски

- Действия подключены по тегам (`@v4`), а тег можно перенести. Используются только официальные: `actions/*` и `gradle/actions`.
  Токен только на чтение, секретов нет, подпись ваша, поэтому ущерб ограничен подменой содержимого APK, и подпись
  вы ставите после того, как сами решили ему доверять. Строже: закрепить действия по хешу коммита
  (`gh api repos/actions/checkout/git/ref/tags/v4 --jq .object.sha`). Хеши я проверить не мог.
- Зависимости Gradle качаются с Google Maven и Maven Central без проверки контрольных сумм: проверка не настроена.
  Включается командой `gradle --write-verification-metadata sha256 help` (нужна сеть), файл
  `gradle/verification-metadata.xml` потом коммитится.
- Версии (AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9, compileSdk 35) согласованы с документацией AGP 8.7
  (Gradle 8.9, JDK 17, API до 35, build-tools 34.0.0 по умолчанию), но сборка не выполнялась.
