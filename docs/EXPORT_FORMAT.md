# Формат зашифрованного экспорта v1

Файл JSON. Реализация: `core/reference-python/skhoron2fa/vault.py`.

```json
{
  "format": "skhoron-2fa-export",
  "version": 1,
  "kdf": {"name": "argon2id", "salt": "<base64, 16 байт>", "iterations": 3, "memory_kib": 65536, "lanes": 4},
  "cipher": {"name": "aes-256-gcm", "nonce": "<base64, 12 байт>"},
  "ciphertext": "<base64, шифртекст + тег 16 байт>"
}
```

- Ключ: Argon2id от пароля, 32 байта. Пароль перед KDF нормализуется в Unicode NFKC и кодируется в UTF-8,
  поэтому `é` одним символом и `e` + combining acute дают один ключ.
- Шифр: AES-256-GCM. Ассоциированные данные: заголовок (все поля кроме `ciphertext`) в виде
  JSON с отсортированными ключами и разделителями `,` и `:` без пробелов. Любое изменение заголовка,
  включая добавление поля, ломает проверку тега.
- Границы при чтении (защита от вредоносного файла): `memory_kib` не больше 262144 и не меньше `8 * lanes`,
  `iterations` от 1 до 10, `lanes` от 1 до 16.
- Открытый текст внутри шифртекста: `{"entries": [...]}`, запись содержит `type`, `issuer`, `account`,
  `secret` (base32 без `=`), `algorithm`, `digits`, `period`, `counter`.

Реализации: Python (эталон, `vault.py`) и Java (`VaultExport.java`, для Android). Совместимость проверена в обе
стороны: файл Python читает Java (`core/test-vectors/export_python.json`), файл Java читает Python
(`tools/check_java_export.py`, шаг 4b в `tools/verify.sh`). Java читает строже эталона: неизвестные поля
заголовка отклоняются, nonce только 12 байт, соль от 8 байт; JSON разбирается собственным строгим разборщиком
(повторяющиеся ключи, дробные числа и глубина больше 16 отклоняются).

Чтобы данные не оказывались в ловушке формата, есть и нейтральный вариант:
`to_otpauth_list` выдаёт обычный список `otpauth://` по строке на запись (без шифрования, хранить осторожно),
который читают другие аутентификаторы.
